    cliffy¶

    Describe a command-line tool in YAML. Get a real Python CLI.

    cliffy reads a manifest that lists your commands, their parameters and the code each one runs, and generates a Typer application from it. Command bodies are plain Python, and any line that starts with $ runs as a shell command, so a manifest can replace a folder of one-off scripts with a single CLI that has help text, typed arguments and subcommands.

    A CLI in 60 seconds¶

    1. Install cliffy (Python 3.11 to 3.15):

    $ pip install cliffy

    2. Write a manifest and save it as hello.yaml:

    hello.yaml
    name: hello
version: 0.1.0
help: Hello world!

commands:
  shell: $ echo "hello from shell"
  python: print("hello from python")
  greet:
    help: Greet someone by name
    params:
      - name: str!
      - --shout|-s: bool = False
    run: |
      message = f"Hello, {name}!"
      print(message.upper() if shout else message)

tests:
  - shell: assert result.exit_code == 0
  - python: assert result.output == "hello from python\n"
  - greet Ada: assert result.output == "Hello, Ada!\n"
  - greet Ada --shout: assert "HELLO, ADA!" in result.output

    3. Load it. cliffy generates the CLI and puts a hello command into your Python environment:

    $ cli load hello.yaml
✨ Generated hello CLI v0.1.0 ✨
$ hello -h

    4. Use it like any other command:

    $ hello shell
hello from shell
$ hello greet Ada --shout
HELLO, ADA!
$ hello --help

 Usage: hello [OPTIONS] COMMAND [ARGS]...

 Hello world!

╭─ Options ──────────────────────────────────────────────────────────────────╮
│ --version                                                                  │
│ --install-completion          Install completion for the current shell.    │
│ --show-completion             Show completion for the current shell, to    │
│                               copy it or customize the installation.       │
│ --help                -h      Show this message and exit.                  │
╰────────────────────────────────────────────────────────────────────────────╯

│ shell                                                                      │
│ python                                                                     │
│ greet   Greet someone by name                                              │
╰────────────────────────────────────────────────────────────────────────────╯

    The tests section at the bottom of the manifest is optional. cli test hello.yaml runs it.

    What you get¶

    • Python and shell in one place. Run scripts are Python; lines starting with $ become subprocess calls. See Shell commands.
    • Typed parameters with a short syntax. name: str! is a required argument and --count|-c: int = 1 is an option. See Params and types.
    • Groups, aliases and templates. db.create nests a command, delete|rm adds an alias and command templates share params between commands. See Commands, groups and aliases.
    • A fast edit loop. cli dev reloads the CLI every time you save the manifest. See Hot-reload dev loop.
    • Tests next to the commands. cli test runs the assertions you keep in the manifest. See Testing manifests.
    • One file to ship. cli build packs the CLI and its dependencies into a single executable zipapp, a single Python script or a native executable. See Building executables.

    How it works¶

    manifest.yaml ──► validate ──► generate Python (Typer or Click) ──► load │ run │ build
    1. cliffy renders the manifest with Jinja2, parses the YAML and validates it against the manifest schema.
    2. It generates one Python module. cli render prints that module, so nothing about the result is hidden.
    3. cli load installs the module as a command, cli run executes it once and cli build packages it.
